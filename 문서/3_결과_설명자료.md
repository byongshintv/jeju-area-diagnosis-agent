# 제주 동네 상권 진단 Agent — 결과 설명자료

제출 버전: 앱 소스 커밋 `c25c493 2026-11-17 14:06` · 자동 테스트 63건

이 문서는 무엇을 왜 만들었는지, 어떻게 동작하는지, 실제로 돌려 본 결과와 검증 방법·한계, 센터에서 쓰는 방법을 적습니다. 이 문서의 표는 모두 동봉 도구를 실행한 출력 그대로이며, 같은 명령으로 다시 만들 수 있습니다.

## 1. 문제 정의

- 제주에서 음식점 폐업이 늘고 있습니다. 서귀포시 일반음식점은 2025년 1~4월에 123곳이 폐업해 전년 같은 기간보다 29.5% 늘었고, 같은 기간 신규 창업 115곳보다 많았습니다(한라일보 2025-05-07). 같은 기간 제주 전체로는 일반음식점 361곳, 휴게음식점(카페 포함) 185곳이 폐업했습니다.
- 제주빅데이터센터에는 읍면동×업종 카드 이용, 외식업 POS, 업종별 매장 수 같은 상권 데이터가 있습니다. 그러나 IT 비전문 도민이 센터 PC에서 이 데이터를 직접 골라 집계하고, 10 미만 값 가림·역산 방지 같은 반출 기준까지 맞추기는 어렵습니다.
- 지금 예비창업자가 동네 상권을 확인하는 길은 전국 단위 상권 서비스를 직접 해석하거나, 센터 컨설팅을 신청해 사람 분석가의 자료를 2주 이내에 받는 것입니다.

**목표**: 자연어 질문 하나로 동네 확인 → 업종 확인 → 데이터 선택·결합 → 순위 계산 → 차트·표 → 보고서 → 반출 점검을 자동으로 끝내, 비전문가가 데이터를 직접 고르고 집계하는 단계를 없앱니다. 결과는 "제주 43개 읍면동 안에서 이 동네가 어디쯤인가"로 보여 주고, 숫자마다 출처와 기간을 붙입니다.

## 2. Agent 구조

```
도민 ─ 질문 입력 / 지도·업종 선택
        │
        ▼
  AI 키 설정됨? ── 예 ──▶ AI 모델: 도구를 골라 최대 8단계 호출, 마지막 단계는 답변만
        │                    (오류·빈 응답이면 규칙 모드로 자동 전환)
       아니오
        ▼
  규칙 모드: 같은 도구를 정해진 순서로 호출
        │
        ▼
  로컬 엔진(이 PC): 등록 도구 11종 실행 · 모든 수치 계산 · 센터 CSV 처리
        │      ├ 허브 스냅샷(동봉) 읽기
        │      └ 센터 CSV(업로드, 메모리) 읽기
        ▼
  결과 조립 → 보고서(인쇄·CSV) → 반출 사전 점검(가림·신청서 설명 초안)
        │
        ▼
  센터: 반출 최종 심사
```

| 주체 | 맡는 일 | 접근 범위 |
|---|---|---|
| AI 모델(선택) | 도구 선택·호출 순서, 진단/비교 판단, 답변 문장 | 도구 결과 요약만 받음(허브 수치, 센터 수치 자리는 자리표시 문구). 파일·네트워크 직접 접근 없음 |
| 로컬 엔진 | 모든 수치 계산, 센터 CSV 읽기·처리, 반출 점검, 보고서 | 이 PC의 동봉 데이터·업로드 파일, 127.0.0.1 서버 |
| 센터 | 반출 최종 심사 | — |

등록 도구 11종: `resolve_region`, `resolve_industry`, `list_datasets`, `profile_dataset`, `query_table`, `diagnose_area`, `compare_areas`, `trend`, `make_chart`, `build_report`, `export_check`. 도구별 하는 일은 `2_데이터_활용_명세` 4절에 있습니다.

판단·자율 수행 범위:

- 모델은 등록된 도구와 허용된 인자로만 작업을 요청합니다. 인자 형식이 틀리면 빈 인자로 처리해 도구가 되묻습니다. 같은 도구를 같은 인자로 반복하지 않도록 프롬프트에 적었습니다.
- 숫자는 도구 결과에 나온 값만 인용하고 출처 데이터 ID와 기간을 붙이게 했습니다(`jeju_agent/prompts/system.md`).
- 제주 밖 지역은 모델을 부르지 않고 되묻습니다.
- AI 호출 오류·시간 초과·빈 응답이면 규칙 모드로 끝내고 사유를 화면에 표시합니다.

### 4.3 반출 규칙별 시험 사례

명령: `python\python.exe tools\export_cases.py`

| 규칙 | 입력 | 기대 | 실제 | 판정 |
|---|---|---|---|---|
| 10 미만 칸 가림 | 제과점 이용자수 7 | 그 칸만 가림 | 2행 이용자수(under_10) | 통과 |
| 합계로 역산되는 칸 | 위 표 + 합계 172 공개 | 같은 열에서 가장 작은 다른 값(편의점 45)도 가림 | 2행 이용자수(under_10), 3행 이용자수(back_calculation) | 통과 |
| 다른 공개값이 없는 합계 | 한 행(7)과 합계 7 | 합계 비공개 | 1행 이용자수(under_10), 합계 비공개 | 통과 |
| 나눠 구한 값(1인당) | 노형동 1.3, 연동 12.5 | 1.3 가림(사칙연산 결과도 최종 결과값) | 1행 1인당 이용건수(under_10) | 통과 |
| 허브 공개 데이터만 쓴 표 | 추자면 점포 수 2(hub:793) | 점검 대상 아님(공개 데이터) | 점검 안 함, 값 2 | 통과 |
| 센터 데이터가 섞인 진단 | 추자면 편의점(가상 센터 데이터 로드) | 근거 표·문장·핵심 지표·비교 막대 모두 점포 수 가림 | 표 가림, 문장 '가림(10 미만)', 지표 가림, 막대 가림 | 통과 |
| 가릴 값이 없는 진단 | 노형동 카페(가상 센터 데이터 로드) | 가림 없음 | 가림 0칸 | 통과 |

- `under_10`은 최종 결과값 10 미만, `back_calculation`은 합계에서 거꾸로 계산되지 않게 함께 가린 칸입니다.
- 역산 가림 사례: 이용자수 열이 카페 120·제과점 7·편의점 45, 합계 172로 공개된 표에서 제과점(7)만 가리면 172 − 120 − 45 = 7로 값이 드러납니다. 그래서 같은 열에서 가장 작은 다른 값인 편의점(45)도 함께 가렸습니다.
- 개발 중 이 시험으로 결함 하나를 찾아 고쳤습니다. 근거 표에서는 추자면 편의점 점포 수를 가렸는데 진단 문장에는 "동종 점포 2개"가 남아 있었습니다. 지금은 표에서 가린 값을 문장·핵심 지표·비교 막대·보고서 본문에서도 함께 가립니다(마지막에서 두 번째 사례).

| 업로드한 가상 센터 데이터로 대정읍 편의점 시간대를 알려 줘. | resolve_region → resolve_industry → diagnose_area | 3회 | 8,532(7,751+781) | 9.1초 |

개발 중에는 `gpt-6-luna`로도 같은 3문항을 AI 모드로 끝냈습니다(문항당 4,765~6,397토큰).

- 셋째 질문에서 모델에 간 도구 메시지에는 센터 시간대 수치가 없고, 화면에는 로컬에서 만든 "센터 데이터 분석 결과" 문단이 따로 붙었습니다.
- 스모크에서 찾은 문제 5건(센터 데이터가 있는 진단에서 허브 공개 수치까지 숨김, 비교 요약에 출처·기간 누락, 모델이 "제주시 노형동"을 통째로 넣어 동네 확인 실패, 시간대 질문에 없는 도구를 찾음, 업로드 직후 센터 데이터를 못 봄)을 고친 뒤 다시 통과했습니다.
- 심사용 ZIP의 `.env`에 평가용 키가 들어 있어 `실행.bat`만으로 AI 모드가 켜집니다. `.env`의 키를 지우면 같은 질문이 규칙 모드로 끝나고 수치는 같습니다(숫자는 두 모드 모두 같은 로컬 도구에서 나옵니다).

### 4.7 재현성

- 같은 ZIP, 같은 질문이면 규칙 모드 결과가 같습니다. 동봉 스냅샷과 가상 데이터(시드 고정)만 쓰기 때문입니다.
- 위 4.1~4.3의 표는 문서를 만들 때 명령을 실제로 실행한 출력입니다. 같은 명령으로 다시 확인할 수 있습니다.
- 최신화: 허브 스냅샷은 `tools\fetch_hub_snapshots.py`로 다시 받을 수 있고(허브 키 필요), 센터 최신 CSV를 올리면 그 기간으로 계산합니다.

## 5. 한계

- 유동인구 지수는 허브 문서에 집계 단위 설명이 없어 사람 수로 말하지 않고 상대 비교로만 씁니다.
- 유동인구는 각 달 1~3일, 버스는 각 달 1일 표본입니다. 월 전체 평균이 아닙니다. 버스 순위는 정류소 주소로 읍면동을 붙일 수 있었던 41곳만 대상입니다.
- 카드·POS 자료는 카드·표본 점포 기준이라 현금 거래가 빠져 있습니다. 임대료·인건비·상권 개폐업률은 분석에 들어 있지 않습니다.
- 점포당 카드 이용금액은 분자(2020년)와 분모(2025-09) 시점이 달라 참고값입니다.
- 센터 자료가 없으면 시간대·요일·메뉴 비중은 제주 전체 값이라 그 동네만의 패턴이 아닙니다.
- 센터 데이터 분석은 형식을 흉내 낸 가상 예시로 시험했습니다. 실제 센터 CSV의 값 분포·결측 양상은 센터 안에서 다시 확인해야 합니다.
- 반출 사전 점검은 대회 게시판에 공개된 기준을 코드로 옮긴 사전 점검입니다. 최종 반출 판정은 센터 심사입니다.
- 결과는 "제주 읍면동 안 상대 위치"이며 창업 성공을 예측하지 않습니다. 화면과 보고서에 강점·주의로만 표시하고 단정하지 않습니다.
- 허브 Open API 실시간 호출(질문할 때마다 최신 값)과 업종별 전체 지도 보기는 다음 단계 기능입니다.
