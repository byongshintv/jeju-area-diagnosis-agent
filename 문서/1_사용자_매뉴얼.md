# 제주 동네 상권 진단 Agent — 사용자 매뉴얼

이 문서는 센터 PC에서 이 프로그램을 처음 쓰는 사람을 위한 안내입니다. 프로그램 구조와 의존성은 `README.md`, 데이터 출처는 `2_데이터_활용_명세`에 있습니다.

## 1. 켜고 끄기

1. ZIP을 원하는 폴더에 풉니다. 바탕 화면이나 `C:\제주상권진단`처럼 쓰기 권한이 있는 곳이면 됩니다.
2. 풀린 폴더의 `실행.bat`를 더블클릭합니다.
   - 처음 실행할 때 Windows가 "Windows의 PC 보호" 창을 띄우면 **추가 정보 → 실행**을 누릅니다. 인터넷에서 받은 bat 파일이라 뜨는 경고입니다.
3. 검은 창이 뜨고 1~2초 뒤 기본 브라우저에 화면이 열립니다. 주소는 `http://127.0.0.1:8765/`입니다. 이 주소는 이 PC 안에서만 열리고 다른 PC에서는 접속할 수 없습니다.

끄기: 검은 창을 닫습니다. 브라우저 탭만 닫으면 프로그램은 계속 돌고 있으니, 다시 `실행.bat`를 누르면 같은 화면으로 돌아옵니다.

## 2. 화면 구성

- **맨 위 메뉴 줄**: 지금 모드(`규칙 모드 (AI 키 없음)` 또는 `AI 모델 <모델 이름>`), 공개 데이터 수, 올린 센터 데이터 수, **센터 데이터 올리기** 버튼.
- **왼쪽**: 예시 질문 3개와 쓸 수 있는 데이터 수, 아래쪽 질문 칸과 **묻기** 버튼. 질문을 하면 질문(Q), "Agent가 한 일"(번호 칸이 한 줄씩 쌓임), 답변(A) 순서로 쌓입니다.
- **오른쪽**: 처음에는 "어느 동네, 어떤 가게인가요?" 판(제주 읍면동 지도 + 업종 고르기). 진단이 끝나면 결과 판으로 바뀝니다.

## 3. 진단하기

두 가지 방법 중 편한 쪽을 씁니다.

- **질문으로**: 왼쪽 칸에 "노형동에서 카페 창업하면 어때?"처럼 동네와 업종을 넣어 묻습니다. `Enter` 또는 **묻기**.
- **지도로**: 오른쪽 지도에서 동네 칸을 누르고, 아래에서 업종을 고른 뒤 **진단하기**.

동네 이름은 행정동(노형동·애월읍 등 43곳), 법정동(아라동 안의 영평동 등 73곳), "제주시 서부" 같은 권역을 알아듣습니다. 업종은 "카페", "한식당", "편의점", "치킨집" 같은 일상어를 카드 업종·상가 분류로 바꿔 씁니다. 동네나 업종이 빠졌거나 여러 곳과 겹치면 후보 버튼을 보여 주며 되묻습니다. 제주 밖 지역을 물으면 제주 읍면동을 다시 묻습니다.

### 결과 읽기

- **제주 읍면동 안에서의 위치(동네 위치표)**: 유동인구 지수·동종 점포 수·점포당 카드 이용금액·버스 승차 인원을 각각 "43곳 중 N위(상위 P%)"로 바꿔 눈금 위 점으로 보여 줍니다. 지표마다 단위가 달라 눈금을 따로 그립니다. 점 옆 낱말(강점·중간·주의)로 읽습니다.
- **결론과 분석 범위**: 위치표 아래에 한두 문장 결론과 "분석 범위와 해석 조건"이 붙습니다.
- **차트**: 유동인구 지도와 월별 추이, 인접 동네 점포 수, 시간대·요일 비중, 메뉴 구성.
- **근거 표**: 화면의 모든 수치를 지표·값·단위·기간·출처 데이터로 정리한 표입니다.
- **출처 꼬리표**: 숫자마다 쓴 데이터 이름과 기간이 붙습니다. 공개 데이터(제주데이터허브)는 실선, 센터 데이터는 **점선 테두리**로 구분합니다.
- **이 결과로 알 수 없는 것**: 표본·기간·단위의 한계를 목록으로 보여 줍니다.
- **쓴 데이터**: 이번 진단에 쓴 데이터의 제공처·이름·기간·구분(공개/센터).

유동인구 지수는 허브가 단위를 밝히지 않은 집계값이라 "명"으로 읽지 않습니다. 같은 지수끼리 비교한 순위로만 씁니다.

### 비교와 추이

- "애월읍과 한림읍 한식당 비교해 줘"처럼 2~5개 동네를 물으면 지표별 막대 쌍, 두 동네가 켜진 지도, 비교 표가 나옵니다.
- "노형동 유동인구 추이"처럼 물으면 월별 추이를 보여 줍니다.

## 4. 센터 데이터 쓰기

센터에서 분석해 받은 결과 CSV를 올리면, 진단의 카드 이용금액·시간대·요일·메뉴 객단가 칸을 그 센터 수치로 바꿔 계산합니다.

1. 맨 위 **센터 데이터 올리기** 버튼을 누릅니다.
2. **CSV 파일 고르기**를 누르거나 CSV 파일을 창 안으로 끌어다 놓습니다. 여러 파일을 차례로 올려도 됩니다.
3. 프로그램이 1행 열 이름을 센터 데이터 명세 70개 시트와 맞춰 어떤 데이터인지 알아보고, 데이터 이름·행 수·기간을 보여 줍니다.
4. 창을 닫고 진단을 다시 묻습니다. 센터 수치가 들어간 칸에는 점선 테두리 꼬리표가 붙습니다.

- 센터 CSV는 받은 그대로 올립니다. 열 이름을 바꾸거나 엑셀로 열어 다시 저장하면 알아보지 못할 수 있습니다. 문자 인코딩(UTF-8·CP949)과 `NA` 빈 값은 그대로 읽습니다.
- 올린 파일은 이 PC 안에서만 계산하고 AI 모델로 보내지 않습니다(설정 `CENTER_TO_LLM=off`, 기본값).
- **가상 예시 데이터 불러오기**: 센터 데이터 형식만 흉내 낸 가상 데이터 6종을 올린 것처럼 등록합니다. 시연·시험용이며 화면에 "가상 예시"로 표시됩니다.
- **모두 지우기**: 올린 센터 데이터를 모두 지웁니다. 데이터 값은 프로그램이 도는 동안 메모리에만 있어 프로그램을 끄면 사라지고, `runtime\uploads\`에는 파일 이름·열 이름·행 수·기간 같은 목록 정보만 남습니다. 이 목록도 **모두 지우기**로 지워집니다.

### 반출 사전 점검 읽기

센터 데이터가 섞인 진단에는 결과 판 아래쪽에 **반출 사전 점검** 칸이 생깁니다.

- **N칸 가림**: 최종 결과값이 10 미만인 칸과, 공개된 합계에서 거꾸로 계산될 수 있어 함께 가린 칸의 수입니다. 가린 값은 근거 표에 `가림`으로, 문장에는 `가림(10 미만)`으로 바뀌고, 핵심 지표·비교 막대에서도 같이 가려집니다.
- **반출 신청서 설명 초안**: 출처·가공 방법·활용 목적을 한 문단으로 만든 글입니다. **복사**를 눌러 반출 신청서 설명 칸에 붙여 넣고 고쳐 씁니다.
- 이 점검은 대회 게시판에 공개된 반출 기준을 미리 적용한 것이고, 최종 반출 여부는 제주빅데이터센터 심사에서 정해집니다.

## 5. 보고서 저장

결과 판 위쪽 버튼을 씁니다.

- **보고서 인쇄**: 브라우저 인쇄 창이 열립니다. 프린터로 인쇄하거나, 대상에서 **PDF로 저장**을 골라 파일로 남깁니다. A4 세로에 맞춰 버튼·입력 칸은 빠지고 결과만 인쇄됩니다.
- **표 CSV**: 근거 표·비교 표를 CSV로 내려받습니다. UTF-8 BOM 형식이라 엑셀에서 더블클릭하면 한글이 깨지지 않고 열립니다. 가린 칸은 빈칸으로 저장됩니다.

## 6. AI 모드 켜기(선택)

AI 키가 없어도 규칙 모드가 같은 도구를 정해진 순서로 실행해 진단을 끝냅니다. AI 모드를 켜면 모델이 질문을 읽고 도구를 스스로 골라 호출하며, 답변 문장을 질문에 맞게 씁니다. 숫자는 두 모드 모두 이 PC의 같은 도구에서 나옵니다.

1. 프로그램 폴더의 `.env.example`을 복사해 같은 폴더에 `.env`라는 이름으로 붙여 넣습니다. 메모장으로 열어도 됩니다.
   - Windows 탐색기가 확장자를 숨기면 `.env.txt`로 저장될 수 있습니다. 메모장 "다른 이름으로 저장"에서 파일 형식을 "모든 파일"로 고르고 이름을 `.env`로 적습니다.
2. 아래 세 줄을 채웁니다.

```
LLM_BASE_URL=https://api.openai.com/v1
LLM_API_KEY=발급받은_키
LLM_MODEL=도구_호출을_지원하는_모델_이름
```

3. 검은 창을 닫고 `실행.bat`를 다시 실행합니다. 위쪽 상태 줄이 `AI 모델 <모델 이름>`으로 바뀌면 켜진 것입니다.

- OpenAI 호환 Chat Completions + 도구 호출(tools) 규격을 지원하는 공급자면 어느 곳이든 됩니다. `LLM_BASE_URL`은 `/chat/completions` 앞까지의 주소입니다. 센터 안 로컬 모델 서버(OpenAI 호환)를 쓸 때도 그 서버 주소를 넣습니다.
- 심사용 ZIP에는 이 세 줄이 채워진 `.env`가 들어 있습니다(River `deepseek-ai/DeepSeek-V4.1-Flash`, 평가 후 폐기). 다른 공급자로 바꿀 때만 고칩니다.
- 비용: 질문 1건에 모델 호출 3~4회, 약 5천~1만 3천 토큰이 듭니다(3문항 실측: gpt-6-luna 4,765~6,397토큰, DeepSeek-V4.1-Flash 8,242~12,735토큰). 공급자 단가를 곱해 운영 비용을 계산합니다. 공급자 콘솔에서 사용 한도를 걸어 두기를 권합니다.
- AI 호출이 실패하거나 시간이 초과되면 그 질문은 규칙 모드로 끝내고 "LLM을 사용할 수 없어 규칙 모드로 답했습니다(사유)"를 함께 보여 줍니다.
- `CENTER_TO_LLM`은 기본 `off`로 둡니다. 이때 센터 데이터 수치는 모델에 가는 메시지에서 빠지고, 화면에는 로컬에서 만든 센터 수치 문단이 따로 붙습니다. `aggregates`로 바꾸면 반출 점검에서 가린 칸이 하나도 없는 진단의 집계값만 모델에 보냅니다.

## 7. 제주데이터허브 키 발급과 데이터 다시 받기(선택)

프로그램은 허브 공개 데이터 스냅샷 10종을 동봉하고 있어 키 없이 동작합니다. 허브 키는 유동인구(583)·버스(613·612) 같은 Open API 데이터를 최신으로 다시 받을 때만 필요합니다.

### 키 발급

1. 제주데이터허브(https://www.jejudatahub.net)에 회원 가입하고 로그인합니다. 가입 때 휴대폰 본인확인이 있습니다.
2. **마이페이지 → 프로젝트 관리 → 프로젝트 만들기**로 프로젝트를 하나 만듭니다.
3. 아래 데이터의 상세 페이지에서 API 데이터를 **프로젝트 담기**로 방금 만든 프로젝트에 담습니다. 프로젝트에 담지 않은 데이터는 호출이 거부(Forbidden)됩니다.
   - 583 읍면동 단위 내국인 유동인구
   - 613 정류소별 버스 이용자
   - 612 버스 정류소 정보
4. 프로젝트 상세 화면의 **프로젝트키**를 복사합니다.

### 키 설정과 다시 받기

1. `.env`(6절 1단계 참고)에 한 줄을 넣습니다.

```
HUB_API_KEY=복사한_프로젝트키
```

2. 프로그램 폴더에서 명령 창(주소 표시줄에 `cmd` 입력 후 Enter)을 열고 실행합니다.

```
python\python.exe tools\fetch_hub_snapshots.py --dry-run
python\python.exe tools\fetch_hub_snapshots.py
```

- `--dry-run`은 받을 목록과 키 인식 여부("키 있음")만 보여 주고 파일을 바꾸지 않습니다.
- 실제 실행은 `sample_data\hub\`의 CSV와 메타 파일을 새로 씁니다. 받지 못한 데이터는 기존 스냅샷이 그대로 남습니다. 미리 `sample_data\hub` 폴더를 복사해 두면 되돌리기 쉽습니다.
- 허브 Open API는 데이터별 하루 호출 한도가 1,000건입니다. 도구는 한 번 실행할 때 호출 수 상한을 두고, 넘으면 멈춥니다. 동봉 스냅샷을 만들 때 583에 256회, 613에 195회를 썼습니다.
- 키는 화면·로그·메타·CSV 어디에도 기록되지 않습니다.
- 받은 뒤 프로그램을 다시 실행하면 새 기간으로 계산합니다.

## 8. 문제 해결

| 증상 | 확인할 것 |
|---|---|
| `실행.bat`를 눌러도 아무 창이 안 뜸 | ZIP을 풀지 않고 ZIP 안에서 눌렀을 수 있습니다. 압축을 먼저 풉니다 |
| 검은 창에 `python\python.exe not found` | 압축을 일부만 풀었습니다. 폴더 전체를 다시 풉니다 |
| 검은 창에 "포트 8765을(를) 열 수 없습니다" | 다른 프로그램이 포트를 씁니다. `.env`에 `PORT=8766`을 넣고 다시 실행합니다 |
| 검은 창이 바로 닫힘 | 명령 창에서 `python\python.exe -m jeju_agent`로 실행해 오류 문장을 확인합니다 |
| 브라우저가 안 열림 | 주소창에 `http://127.0.0.1:8765/`을 직접 입력합니다 |
| 위쪽에 "서버에 연결하지 못했습니다" | 검은 창이 닫혔습니다. `실행.bat`를 다시 실행합니다 |
| 센터 CSV를 알아보지 못함 | 1행이 센터 명세의 영문 열 이름인지 확인합니다. 엑셀에서 다시 저장한 파일 대신 받은 원본을 올립니다 |
| AI 모드가 안 켜짐 | `.env` 파일 이름(`.env.txt`가 아닌지)과 세 줄(`LLM_BASE_URL`·`LLM_API_KEY`·`LLM_MODEL`)이 모두 채워졌는지, 프로그램을 다시 실행했는지 확인합니다 |
| 허브 재수집이 "키 없음" | `.env`의 `HUB_API_KEY` 줄과, 데이터를 프로젝트에 담았는지 확인합니다 |

실행 기록은 `runtime\logs\`에 남습니다(요청·단계·소요 시간. 키와 원본 데이터 값은 기록하지 않습니다). 문제를 알릴 때 이 폴더를 함께 전달하면 원인을 찾기 쉽습니다.

## 9. 개인정보와 보안

- 이 프로그램은 `127.0.0.1`(이 PC)에서만 열립니다. 외부에서 접속하는 서버를 열지 않습니다.
- 센터 데이터는 기본 설정에서 AI 모델로 보내지 않습니다. 모델에는 허브 공개 수치와 "센터 수치는 화면에 별도 표시" 자리표시 문구만 갑니다.
- 올린 센터 CSV의 값은 프로그램이 도는 동안만 메모리에 둡니다. 디스크(`runtime\uploads\`)에는 파일 이름·열 이름·행 수·기간만 남고, **모두 지우기**로 지울 수 있습니다.
- 이 ZIP에는 허브 키가 들어 있지 않습니다. AI 키는 심사용 평가 키만 `.env`에 있고 평가 후 폐기합니다. `.env`에 넣은 키는 이 PC에만 남으니, PC를 넘길 때는 `.env`를 지웁니다.
